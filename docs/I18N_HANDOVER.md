# 영어 지원(i18n) 인계 문서

> **주의: 이 문서를 읽었다고 바로 작업을 시작하지 말 것.** 사용자가 "시작해"라고 명시적으로
> 말할 때만 아래 단계를 진행한다. 읽고 이해했으면 현재 어느 단계부터 시작하면 될지 되묻고 대기한다.

## 요청 배경
현재(2026-09-29 기준) 게임은 튜토리얼·손님 대사·이벤트·신문·엔딩까지 전부 한국어 문자열이 로직 코드 안에
그대로 박혀 있다 (`greet: '...'`, `lines: { sold: '...' }` 식). 설정 화면에서 언어를 바꿀 수 있게
해 달라는 요청 — 전체 번역(본문 포함) 기준.

## 규모 (되짚어볼 것)
- `js/data/*.js` + `js/systems/*.js` 합쳐 한글 글자수 약 **12만 5천자**.
- 손님 틀(talks.js 74개 + arcs_realm/wonders/trade 각 40\~50개) 세어보면 400개 안팎의 손님·대사 뭉치.
- 엔딩 28종, 이벤트(events.js), 신문 문구(news.js), 편지(letters.js) 별도.

## 구조적으로 걸리는 것
1. **문자열이 로직에 직접 박혀 있다** — 지금 `WS.data.customers`, `WS.data.endings` 등의 객체 리터럴
   안에 한국어 대사가 바로 값으로 들어 있다. 언어 전환이 되려면 이 문자열들을 로케일 키로 뽑아내고,
   런타임에 현재 언어에 맞는 값을 찾아오는 계층이 하나 더 필요하다 (지금은 그 계층이 없다).
2. **조사(josa) 자동 처리가 텍스트에 녹아 있다** — `{item|을}`, `{tag|과}` 같은 템플릿이
   `js/systems/NewsManager.js`의 `josa()`와 `WS.util.fill()`로 채워진다 (받침 유무로 을/를, 이/가,
   은/는, 과/와, 으로/로 자동 선택). **영어는 이런 문법이 없다** — 그대로 옮기면 의미 없는 코드가 되고,
   문장 자체를 영어 어순으로 다시 써야 한다. 즉 "문자열만 치환"으로 안 끝나고 **문장 구조 재작성**이
   같이 들어간다.
3. **동적 삽입이 많다** — `${en.short}`, `${a.tag}` 처럼 세력 이름·손님 이름이 런타임에 꽂히는 문장이
   전 데이터 파일에 흩어져 있다 (이번 세션에 이 패턴에서 조사 버그를 두 번 잡았다 — `Clash.js`,
   `talks.js`). 번역 시 이 삽입 지점을 영어 어순에 맞게 다시 배치해야 한다.
4. **지하 도박장(2026-09-29 추가)** — 대사·해설·결과 문구가 `js/data/gambler.js`(카이·감찰관·마담)와 `js/ui/CasinoView.js`(입장·단속·큰 판 장면, 게임 안내, 딜러 반응 `SAY`)에 흩어져 있다. 한국어 조사를 문자열에 박아 둔 곳이 많으니 같이 옮길 것. 흐름은 `docs/CASINO_HANDOVER.md`.
5. **UI 크롬(버튼·메뉴·HUD 라벨)**은 `js/ui/UIManager.js`, `css/*.css`, `index.html`에 있고
   본문 콘텐츠보다 훨씬 적은 양이라 상대적으로 빠르다.

## 추천 진행 순서 (한 세션에 다 끝내려 하지 말 것)
1. **1단계 — 로케일 인프라만** (콘텐츠 번역 없이)
   - `WS.data.config.lang` 같은 현재 언어 상태 + `WS.util.t(key, ctx)` 류의 조회 함수 추가.
   - 기존 문자열을 깨지 않는 선에서, UI 크롬 라벨부터 로케일 키로 분리 (`js/data/locale/ko.js`,
     `js/data/locale/en.js`).
   - 설정 화면에 언어 토글 UI만 붙이고, 아직 본문(대사·엔딩)은 한국어 그대로 두어도 동작하게.
   - 커밋 후 반드시 `tools/sim.js` 로 회귀 확인 (문자열 조회 계층이 기존 로직을 안 건드렸는지).
2. **2단계 — 본문 번역, 묶음 단위로**
   - 튜토리얼(1\~4일) → 기본 세력 손님(customers.js) → talks.js(왕좌/충돌) → arcs_*.js(연결 손님) →
     endings.js → events.js → news.js 순서 추천 (플레이어가 먼저 보는 순서, 초반부터 완성도 확인 가능).
   - 각 파일 번역 끝날 때마다 커밋 + 짧게 영어로 플레이해서 어색한 삽입 문장 없는지 확인.
   - 조사 삽입 지점은 영어에서는 대부분 그냥 제거하거나 어순을 바꿔 자연스럽게 — 기계적 1:1 치환 금지.
3. **3단계 — 마무리**
   - 폰트: 현재 Gowun Batang/Noto Sans KR (한글 전용 느낌 폰트) — 영어 문장에 그대로 쓰면 어색할 수
     있어 라틴 문자용 폰트 별도 지정 검토.
   - 영어 플레이스루 전체(30일) 한 번 실제로 돌려서 어색한 문장·잘린 텍스트·placeholder 안 풀린 곳 확인.

## 참고할 기존 코드
- `js/systems/NewsManager.js` — `josa()`, `fill()` (조사 자동 채움의 원본 구현)
- `js/data/talks.js` 상단 주석 — 현재 데이터 파일 구조와 흐름 설명이 잘 되어 있음
- `docs/HANDOVER.md` — 전체 프로젝트 구조 인수인계
- `docs/DESIGN_CONVERGENCE.md` — 세력·엔딩 설계 의도 (번역 톤 잡을 때 참고)

## 이번 세션에서 한 일 (여기서부터 이어감)
- 범위만 조사함 (글자수, 구조적 난점). **코드/데이터 변경은 아직 없음.**
- 사용자는 "전체 번역"을 원하고, 소넷(Sonnet) 모델로 진행 예정, 새 세션에서 이어감.
